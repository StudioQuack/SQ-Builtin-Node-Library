# Databases & Storage

SQL, document, time-series, graph, vector, cache, and messaging providers. **One node per distinct API / auth surface**; the designer picks an `operation` (never a separate node per verb; provider triggers are `trigger.listen` on the same node). Almost every node is **one INPUT + one OUTPUT**.

The **customer owns the database** (or broker / index). StudioQuack stores only connection secrets in the daemon secret store and never logs them. **No host filesystem paths** (no `filePath`, `localPath`, `unix_socket`, `credsFile`, or TLS CA *files*). PEM material and wallets use password / `file` (platform ref-id) fields.

Wire-compatible hosts share one node plus an `engine` (or equivalent) config when protocol **and** operations match. A second node exists only when auth, official HTTP surface, or operations diverge. Redis Streams and Redis Query Engine vector search are operations on Redis, not extra nodes. Vector stores live **only** in this catalog (not a second copy under AI & Machine Learning). Callers own encryption, network exposure of the client host, and each vendor’s ToS.

Implementer specs: [`docs/specs/databases-storage/`](../specs/databases-storage/). Researched 2026-08-20.
