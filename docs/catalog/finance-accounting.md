# Finance & Accounting

StudioQuack models payments, books, open banking, cards, and market data as **one node per API provider**. Charge vs refund vs webhook listen are `operation` values — provider webhooks are `trigger` (`kind: ingress` on the same node; BPMN message events — there is no Webhook node). Ports are **one INPUT + one OUTPUT**. Cardholder data never enters the graph: use processor tokens only; bind API keys as StudioQuack password secrets; never log PAN, bank account numbers, or signing secrets. Customer holds the merchant/broker account and its ToS; StudioQuack does not custody funds.
