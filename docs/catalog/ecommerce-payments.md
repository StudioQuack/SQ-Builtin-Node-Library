# E-Commerce & Payments

StudioQuack models storefronts, marketplaces, print-on-demand, fulfillment, returns, and reviews as **one node per API provider**. Storefront webhooks become a `trigger` operation on the same store node. Ports are **one INPUT + one OUTPUT**. The customer owns the merchant account; bind Admin/API tokens as StudioQuack secrets; never log storefront passwords or order PII beyond the workflow. Card capture still goes through a **Finance** PSP node (Stripe, PayPal, …) unless the platform’s own payments API is the source of truth.
