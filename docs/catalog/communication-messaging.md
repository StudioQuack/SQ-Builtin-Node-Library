# Communication & Messaging

Provider nodes for email, chat, SMS, voice, push, and scheduling-comms APIs. One node per API provider; the designer picks work via an `operation` parameter (action vs trigger collapse here — `listen` is an operation, not a second node). Discord incoming webhooks are an auth mode on Discord, not their own node. Ports are one INPUT and one OUTPUT; none of these providers need FUNCTION ports. Each **done** row is `nodes/<kebab-slug>/{node_definition.json,api_spec.json,README.md}` on `OfficialApiNode`. `listen` / `send-and-wait` are `kind:ingress` (BPMN message events) — not a Webhook node.
